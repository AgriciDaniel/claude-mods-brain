# Hook Middleware Chain

Every hook for one event joins a single middleware chain, Koa style: each hook receives `($, e, next)`, and `next(e)` runs the hooks after it and finally Claude Code's own behavior, resolving to the event's result (C-API-006). The first hook is outermost: it sees the event before everyone else and the result after everyone else, and it decides whether the rest run at all (docs-mods-events L285). A hook registers with `on(pattern, matcher?, hook)`, which returns a registration with one `.catch` (C-API-010).

## The three arguments

| Arg | Type (2.1.288) | Notes |
|---|---|---|
| `$` | `EngineInterface` | Frozen; core namespaces plus any added by `engine.create` (types 2.1.288 L4203-4213). See [[Mods API Namespaces]]. |
| `e` | `Frozen<Args<N>>` | Deeply frozen plain data; assigning throws. Change it by passing a copy to `next` (docs-mods-events L49). |
| `next` | `Next<N>` or `StreamNext<N>` | Callable plus members below (types 2.1.288 L6118-6200). |

`next` members (C-API-014):

| Member | What it is | Evidence |
|---|---|---|
| `next(e)` | Runs the hooks beneath, then core. Called with no argument it rejects; each call runs everything beneath again. | types 2.1.288 L6106-6111 |
| `next.signal` | `AbortSignal` that aborts when the dispatch is abandoned: user interrupt, a hook above settled first, or this hook's budget ran out | types L6137-6144 |
| `next.origin` | `{ plugin, tier }` of whoever raised the event; core is `{ plugin: 'engine', tier: 'core' }` | types L6158-6169; docs-mods-reference L39 |
| `next.budget` | `{ ms, remainingMs }`, read fresh on every access | types L6180-6190 |
| `next.to(e, tier)` | Continue at `append`, `builtin` or `core`, skipping links between. Managed mods only. | types L6125-6136 |
| `next.is(pattern, e)` | Type predicate for glob hooks: `next.is('tool.call', e)` | types L6145-6152 |
| `next.event` | The event name as a value, for glob hooks | types L6153-6157 |
| `next.trace` | Frozen list of what each link beneath did on the latest `next()` | types L6170-6178 |
| `next.error`, `next.called` | Only inside a `.catch` handler | types L1012-1023 |

## `on` and matchers

```ts
on(pattern, hook)
on(pattern, matcher, hook)   // returns Registration<F> with .catch(handler)
```

Signature: types 2.1.288 L6343-6346. Patterns are an event name, `'*'`, a namespace glob such as `'tool.*'` or `'classic.*'`, or a negation such as `'!tool.call'` (types 2.1.288 L4745, L7005, L6103). `'*'` matches every event except `telemetry.log` and `telemetry.mark` (docs-mods-events L90).

A matcher is an object compared with `e` field by field; every field must match (C-API-008):

| Matcher value | Matches when | Example |
|---|---|---|
| scalar | `===` | `{ tool: 'Bash' }` |
| array | any element matches | `{ tool: ['Edit', 'Write'] }` |
| RegExp | tests the value as a string | `{ tool: /^mcp__github__/ }` |
| object | partial match of a nested object | `{ origin: { kind: 'peer' } }` |

Paraphrase (types 2.1.288 L5491-5499): `{ startsWith: 'p4' }` is a partial object, so it never matches a string. A matcher also narrows `e` at compile time: with `{ tool: 'Bash' }`, `e.command` is a `string`.

> [!warning] Duplicate registration
> Registering one event twice without a matcher fails the load with `on("session.start") is registered twice without a matcher` (docs-mods-events L92). Put everything for that event in one hook, or give each registration a distinct matcher.

## Glob hooks

```ts
import type { Register } from 'claude-code'

export const register: Register = (on) => {
  on('session.*', async ($, e, next) => {
    $.ui.log('event ' + next.event, { to: 'debug' })
    if (next.is('session.end', e)) $.ui.log('ending: ' + e.reason, { to: 'debug' })
    return next(e)
  })
}
```

`next.is` narrows `e` to the selected member; a pattern outside the hook's coverage is a compile error (types 2.1.288 L4757-4777).

## Error handling with `.catch`

```ts
on('tool.call', { tool: 'Bash' }, guard).catch(async ($, e, next) => {
  // next.error.kind is 'throw' or 'timeout'
  return { deny: 'Command guard failed (' + next.error.kind + '), command not run.' }
})
```

Rules (types 2.1.288 L8683-8700, L1002-1023, L4839-4858):

- One `.catch` per registration; a second throws, as does one after `register` returned or one on `engine.create`.
- The handler gets a fresh 1,000 ms grace (`catchMs`), on the same stopping clock.
- `next.error` is `{ kind: 'throw' or 'timeout', message?, budget }`; `next.called` says whether the failed hook had called `next`.
- Inside the handler `next` is replay safe: if the hook had called it, `next(e)` returns the settled result without running anything beneath again.
- On a streaming event the handler is itself a generator.

## What failure does without `.catch`

When a hook throws, outruns its budget, or returns a shape the site refuses (C-API-011, docs-mods-events L305-312):

- failed before calling `next`: it is skipped and the next handler runs in its place
- failed after `next` resolved: that result stands, nothing runs twice
- returning nothing (`undefined`) counts as a failure (types 2.1.288 L6109-6110)

A line names the mod, event and reason, for example `my-mod: tool.call hook skipped: threw Error: boom` (docs-mods-events L312). This fail-open default is why every guard needs `.catch`; see [[Build a Tool Call Guard Flow]].

## Reading the trace

`next.trace` entries carry `index`, `plugin`, `tier`, `event`, `outcome`, `reason?`, `ms`, `chunks?`, `received`, `returned` (types 2.1.288 L12420-12456). Outcomes: `returned`, `passed`, `skipped`, `kept`, `expired`, `caught`, `rejected` (L12458-12470). `skipped` with reason `bypassed by <plugin>` means a managed mod used `next.to`.

## Every `$` call is a chain too

Each mods API call raises an event named `<namespace>.<method>` (such as `fs.read`, `model.complete`, `ui.open`) through the same machinery, so an earlier mod can observe, rewrite, answer `{ value }` or `{ deny }` (C-API-040; docs-mods-reference L156-158; types 2.1.288 L6395-6740). Calls from inside a hook run "through every hook but the calling one" (types 2.1.288 L2810-2813), which prevents a mod from recursing into itself.

## Recommendations

- Return `next(e)` (or the awaited result) from every hook that does not mean to answer; returning `undefined` is a failure. EVIDENCE-BASED
- Attach `.catch` to every hook that denies, holds or rewrites, so it fails closed. EVIDENCE-BASED
- Use matchers, not `if` checks, for the event filter: they narrow types and keep the hook from running at all. EVIDENCE-BASED
- Use `next.trace` in tests to assert which link answered; see [[Testing Kit]]. PRACTITIONER
