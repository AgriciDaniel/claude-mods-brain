# Claim Verification Flow

A mods claim is verified when a rank 1 source (the official docs captures or the 2.1.288 typings, cited by line range) supports it and a second, independent source agrees. One rank 1 source alone leaves the claim SINGLE-SOURCE; a conflict leaves it contradicted with a `> [!contradiction]` callout that names the winner. On 2026-10-03 the ledger holds 301 rows: 225 verified, 55 SINGLE-SOURCE, 14 contradicted, 6 unverified. This flow is how a row gets one of those verdicts and how it keeps it after a release.

## Trigger

- A note states a fact about mods behavior, limits, names, or costs that has no claim id yet.
- A source disagrees with an existing row (a new #91870 staff comment, a docs edit, a drift report).
- [[Research Refresh Workflow]] lists a claim whose typings line range moved.

## Prerequisites

- The evidence ranking from `references/orchestration/LANE_BRIEF.md`: (1) docs at code.claude.com and the typings `.raw/captures/types-2.1.288/`, (2) official example code, (3) Anthropic blog and claude.dev, (4) the #91870 thread, (5) independent research, (6) community repos, (7) the seed report.
- The captures in `.raw/captures/` and the ledger at `references/claim-ledger.md`.

## Steps

1. Write the claim as one narrow, testable sentence. "`context` past 100,000 characters reaches the model as a head plus a path" is testable; "mods handle big context well" is not.

2. Find the rank 1 source in the docs capture and record the line:

```bash
grep -n "100,000\|head + path" .raw/captures/docs-2026-10-03/plugins-mods-*.md
```

3. Find the typings line range. Cite as `types 2.1.288 L<start>-<end>` and read the full JSDoc block, not just the matching line:

```bash
F=.raw/captures/types-2.1.288/claude-code/index.d.ts
grep -n "past 100,000" "$F"            # L12025
sed -n '12019,12026p' "$F"
```

Docs and typings count as two sources only when both independently state the fact. The typings are generated by the binary and the docs are written by people, so agreement between them is strong evidence.

4. Look for the second source when step 2 or 3 came up empty, in rank order: official example code (`.raw/captures/official-mods/code-modernization-1.0.0/`), the launch blog and claude.dev captures in `.raw/captures/web-2026-10-03/`, then a #91870 comment, cited by its comment URL:

```bash
grep -n "issuecomment" .raw/captures/web-2026-10-03/gh-issue-91870.md | grep -i "budget" | head
```

5. Assign the verdict:

| Evidence found | Verdict | Confidence tag |
|---|---|---|
| Rank 1 plus an independent second source agree | verified | evidence-based |
| Only one source of any rank | SINGLE-SOURCE | evidence-based if rank 1, else practitioner |
| Two sources disagree | contradicted | contested until resolved |
| Source unreachable or not yet read | unverified | contested |
| Only the seed report | SINGLE-SOURCE, never promoted to a deliverable | folklore |

The worked example above stays SINGLE-SOURCE: the typings state the 100,000 and 200,000 character thresholds, and no docs page or comment repeats them (C-API-020).

6. Write the row:

```
| C-API-020 | `context` strings ... past 100,000 characters (200,000 together) reach the model as a head plus a path. | evidence-based | types L12019-12026, L8433-8441 | none | SINGLE-SOURCE | 2.1.288 |
```

7. For a conflict, add a callout in the note that uses the claim. State both sides, the evidence rank of each, and the winner:

```markdown
> [!contradiction]
> The seed report says a disposable project isolates a trial load (compass-report, section 4).
> The docs say a mod reaches files anywhere the user can (docs-mods-overview), and absolute
> paths are used as given (types 2.1.288 L3009-3014). Docs win; see C-SEC-062.
```

Real contradictions on 2026-10-03 include C-SEC-063 (Pluto said mods are off by default; docs say on from 2.1.287), C-ECO-002 (the `mods/README.md` still describes the old gate), and C-PAT-029 (a 2.1.282 comment said `claude plugin test` cannot set `userConfig`; 2.1.288 typings declare `TestOptions.options`).

8. Tag the claim with a tested-on version. A pre-release thread report keeps its build (`2.1.272`), never the current one, unless re-checked.

9. Spot-check five random verified rows per refresh against their cited lines ([[Source To Claim Spot Check Probe]]).

## Outputs

- A claim row with source, second source or `none`, verdict, and tested-on version.
- Inline citations in the note: `(docs-mods-events)`, `(types 2.1.288 L4803-4837)`, `(C-API-012)`.
- A contradiction callout and a row in the lane `contradictions.md` when sources conflict, merged into [[Contradictions Register]].

## Gates

- Every SINGLE-SOURCE claim used in a deliverable says so in the sentence or a caveat. EVIDENCE-BASED
- No row cites only `compass-report`. EVIDENCE-BASED
- Quotes are verbatim and at most 15 words, or labeled "Paraphrase:". EVIDENCE-BASED
- Typings line ranges point at the JSDoc that states the fact, checked with `sed -n`. PRACTITIONER

## Failure Modes

| Symptom | Cause | Fix |
|---|---|---|
| Docs and typings disagree | Docs lag the binary ("as of v2.1.287") | Typings win for the installed build (C-LIF-043); record the lag |
| Thread report contradicts the docs | Report from a pre-release build | Keep it with its build number; mark contradicted or stale |
| Two "sources" are the same text | A blog quoting the docs | Count it once; look for an independent source |
| Line range off after refresh | New typings file | Re-grep in the new capture; update the range and tested-on |
| Runtime behavior claimed with static evidence only | No dynamic trial allowed ([[Read Only Audit Decision]]) | Mark unverified or practitioner |

## Rollback

Claim rows are text in git. Revert a wrong verdict with `git checkout -- references/claim-ledger.md` or edit the row back; a removed contradiction callout is restored the same way.

## Caveats

- Typings are rank 1 for the build that wrote them only; the 2.1.288 capture says nothing about 2.1.289.
- Runtime-only claims (paint, timing, UI attribution) cannot be verified statically; they stay in [[Unverified pre-release security findings on current builds]] or [[Evidence Coverage Not Yet Verified]] until an owner-approved trial.
